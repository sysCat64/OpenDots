### The candidate (smallest possible)

## 11. Owner authorization and unauthorized side effects (`owner-auth.json`)

Production contract (not invented): **401** missing / wrong owner token (`app.ts`), **403** scope denial (`runtime-scope.ts` through `Platform.handle`). Real local endpoints, 13 cases: authorized allowed; missing token (run, connect, workspace API, runtime info) 401; wrong token 401, including a **same-length** wrong token; wrong scope 403 (unknown thread, thread of Dot A through Dot B's route, unknown agent, body / route agent mismatch, stop on another Dot's thread, a route that is not enabled, another thread's events). For **every** unauthorized case: **provider 0, tool executions 0, durable run / event writes 0** (conversation-table hash, thread bindings, run and event counts all unchanged), and the rejected credential is never echoed. In the real browser a wrong token shows the unlock form and nothing loads (provider 0); the correct token works.

**Fact, recorded and not changed:** `OWNER_TOKEN` is required only for a non-loopback `HOST` (`index.ts:16`). On default loopback without it the boundary is Host / Origin / Sec-Fetch-Site only: cross-origin, cross-site and a foreign Host header (DNS rebinding style) are rejected (403) and cause no provider call. **Recommendation: require `OWNER_TOKEN` in the local-first baseline.** The token is kept in browser `sessionStorage` by design (`src/client/api.ts`), never rendered into the DOM.
