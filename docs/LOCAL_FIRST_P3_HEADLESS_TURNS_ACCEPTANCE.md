**Status: PASS in a scratch worktree (P3: PASS accepted at review). Classification: an offline validated headless-turn integration candidate. Production adoption is NOT yet approved.** The local adapter, the tests, the evidence, the harness changes and the helpers (`tests/p3/*`, `p3-evidence/*`) are **not** in the main worktree; only this document and the design update are. P5 is GO after this closeout and is not started; P2a-9 stays optional / HOLD; P2b-1 is not started.

Scope: `/private/tmp/opendots-p2a1.FV0LOx`. Nothing in main was changed, committed, pushed or tagged by the experiment. Production `src/`, `package.json` and the lock are at the scratch baseline. No live API was used (no OpenAI / ChatGPT Plan, no CopilotKit Intelligence, no Slack, no Voice Realtime, no telemetry, no external network).

**Question answered:** can headless turns (scheduled tasks and voice compute) execute fully in-process through the same local durable AgentRunner, coexist safely with browser runs, preserve the current-turn output semantics, and be aborted through `runner.stop`? **Yes, in this offline PoC.**

## 2. The production headless path, read from the real source (`inventory.json`)

| Item                      | Where / what                                                                                                                                                                                                          |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| entry point               | `runThreadTurn`, `src/server/headless.ts:23`                                                                                                                                                                          |
| callers                   | only `Platform.turn` (`src/server/platform.ts:178`, calls `runThreadTurn` at :186)                                                                                                                                    |
| `Platform.turn` callers   | the scheduled-task callback `src/server/index.ts:112`; voice compute `src/server/voice.ts:184`; the voice receipt `src/server/voice.ts:222`                                                                           |
| scheduled path            | `Runner.tick` (`src/server/runner.ts:43`: one task at a time, an `AbortController` per claim whose abort reasons are `Error` objects) calls the callback, which calls `platform.turn(threadId, claim.prompt, signal)` |
| Intelligence dependencies | `fetch(runtimeUrl + '/info')` that must report `mode: 'intelligence'` (`headless.ts:33`, schema :18); `new IntelligenceAgent({ url: info.intelligence.wsUrl, … })` (:41, :42)                                         |
| explicit history          | `Platform.history` (`platform.ts:134`), called only by `VoiceService.start` (`voice.ts:65`)                                                                                                                           |

**Production `RunAgentInput` of a headless turn:** `agent.threadId = threadId`; the run id is generated by `agent.runAgent()`; the agent holds **exactly one** user message (id `randomUUID()`, with the `opendots:voice_receipt:` prefix and `metadata` for a voice receipt; content = the prompt); **no client tools**; **no history is loaded**.

**Abort:** a signal `abort` calls `agent.abortRun()`; after `runAgent()` returns, `signal.throwIfAborted()` **throws the signal's reason**. A partial text is **not** returned.

**Errors:** `onRunErrorEvent` sets `runError = new Error(event.message)` (**the code is not carried**); `currentTurnText(newMessages, runError)` throws it before anything else.

## 3. The `currentTurnText` contract (exact, from `src/server/headless.ts`)

`currentTurnText(messages, error?)` is a **pure function** and is imported directly as the oracle: it throws `error` if given; otherwise it takes the messages the run **added** (`result.newMessages`), keeps those with role `assistant`, takes the **last** one's `content`, and throws `"The current compute turn returned no assistant response."` unless that content is a non-empty (after trim) string; the content is returned **as is** (no trimming). The pure contract table (`current-turn-text.json`) pins each of these. In production `newMessages` is what the agent holds beyond the one prompt it started with.

## 4. The local adapter candidate (`tests/p3/local-headless.ts`, scratch only)

`runLocalThreadTurn(deps, threadId, prompt, signal, metadata?)`, same observable contract as `Platform.turn`:

1. `signal.throwIfAborted()`; `workspace.requireThread(threadId)`; the Dot must exist (the local version of the `/info` check);
2. build the one user message (voice-receipt prefix and metadata as in production) and a `RunAgentInput` `{ threadId, unique runId, state {}, messages [that one message], tools [], context [], forwardedProps {} }`;
3. an agent like the runtime's (`setMessages`, `setState`, `threadId`, as `handleRunAgent` does) and **`runner.run({ threadId, agent, input })` in-process** (exactly what `handleSseRun` calls); no `/info`, no `IntelligenceAgent`, no socket, no new provider abstraction;
4. on the signal's `abort`, `runner.stop({ threadId, runId })` (production: `agent.abortRun()`);
5. when the run completes: `signal.throwIfAborted()`, then the run's events are folded with the reducer from `[prompt]` to get `newMessages`, and **the production `currentTurnText(newMessages, runError)`** returns or throws.

`DotAgent`, the provider and the tool semantics are unchanged. This is a **validated P3 scratch candidate**, not a production API.

## 5. Schedule stand-in (the production `Runner` and `Store`)

`store.createTask` + `workspace.bindTask` + `Runner.tick()` with a callback of the production shape (`taskThread` → progress → `turn(threadId, claim.prompt, signal)` → `{ text, sources, sample }`).

- **S1**: `RUN_STARTED` 1, `RUN_FINISHED` 1, `RUN_ERROR` 0, one provider request, `isRunning` false, the task `completed` with the result text **equal to the oracle** (the production `currentTurnText` on the real client's `newMessages`).
- **S2, a thread that already holds a browser turn**: the provider request of the scheduled turn has `system` 1, **`user` 1, `assistant` 0, `tool` 0** and the new prompt only; both runs are durable in the same thread; a fresh client reconnect shows both user prompts and both assistant answers **exactly once**; provider requests on reconnect 0.
- **Tool-using turn**: one tool call, one result, the final text exactly once; `currentTurnText` is the **final assistant text** (`Tool list_space_pages result received: []`), not the tool result; equals the oracle.
- **Matrix** (`current-turn-text.json`): plain, tool, multi-chunk, schedule: local == oracle, string for string, no normalizer.

## 6. Voice-compute stand-in and the history decision

The compute stand-in follows `VoiceService.compute` (a per-tool-call-id map; `AbortSignal.any([job.controller.signal, timeout])`) and the receipt follows `syncReceipt` (metadata `{ opendotsSource: 'voice_receipt' }`, id prefix). **The caller obtains context explicitly** with the local analogue of `Platform.history` (`localHistory`: user/assistant text only, last 12, joined by newline, last 12,000 characters); the turn itself receives only the request: the provider saw `user` 1, `assistant` 0, `tool` 0, and the earlier conversation text was **not** in the turn input. `currentTurnText` equals the oracle. The idempotence of `compute()` is the caller's; the receipt message carries the prefix and metadata in the durable `RUN_STARTED.input`.

**`history()` contract** (`history-contract.json`): 31 seeded messages including tool messages; the result is exactly 12,000 characters (the cap binds), at most 12 entries, only `user:` / `assistant:` lines (the tool turn contributes its assistant **text**, never a tool message).

**Headless product decision: confirmed parity with the current production behavior (read from the source and exercised in P3):**

```text
Background / headless `turn` does NOT implicitly load thread history.

It receives only context explicitly supplied by its caller.

Persistent thread membership is independent from model-input history.

Voice or other callers that need conversation context obtain it
explicitly through the history API / caller-side composition.
```

The local runner could supply history, but P3 does not change behavior for that reason.

## 7. Abort (`abort.json`)

A Runner-style `controller.abort(new Error('Run stopped.'))` on a slow turn: **`runner.stop` was called once with the correct thread and run id**; the turn **rejected with the identical error object** (the production contract); the durable log holds the partial text once (`chunk-01 chunk-02 chunk-03 `), `TEXT_MESSAGE_END` 1, `RUN_FINISHED` 1, `RUN_ERROR` 0 (the P2a stop semantics, same runner path); the provider saw the abort and no further request; `isRunning` false. A timeout propagates as a `TimeoutError`; an already-aborted signal throws its reason and starts nothing (provider 0, no run). No partial text is returned and no `AbortError` is invented: both follow the production source.

## 8. Same-thread concurrency (single writer per thread)

- **C1 browser wins**: with a browser run active (held at the provider), a background turn is rejected **synchronously by the runner** (`RunRejectedError`, `THREAD_ALREADY_RUNNING`): provider 0, tool 0, no durable row, one run; the winner was not stopped; the browser completes normally.
- **C2 background wins**: with a background run active, a competing browser run executes no provider call or tool and writes nothing (the real client's `runAgent` resolved with no new message: the surface of the loser is **not** fixed by P3); the background completes.
- **Race**: 20 attempts, both start orders and offsets of 0 to 25 ms (10 won by the browser, 10 by the background): in every attempt exactly **one** provider request, one durable run, `RUN_STARTED` 1, `RUN_FINISHED` 1; the loser left nothing.
- **Different threads**: a held background turn on thread A did not block a browser turn on thread B; B finished while A was still running; A then finished with its full text. No global lock.

## 9. Coexistence and replay across processes

Separate processes on one database file (`headless-to-browser-replay.json`, `browser-to-headless.json`): a headless turn in one process, then a fresh reader process: the headless prompt and answer appear **exactly once**, `RUN_STARTED` 1 / `RUN_FINISHED` 1, provider 0, tool 0, **repair write 0**, DB logical hash unchanged. Browser turn, then a headless turn in another process (the provider saw only the scheduled prompt: `system` 1, `user` 1), then a reader in a third: both runs present exactly once (4 messages, 2 runs), provider 0, repair write 0.

## 10. Error propagation

An uncoded provider error is **thrown**, never returned as text; the thrown `Error` has the message of the durable `RUN_ERROR` and **no `code` property** (production parity); the scheduled task is `failed` with that message. A coded error (the usage-limit code) keeps its **exact code in the durable `RUN_ERROR`**; the turn throws the message only; nothing infers a usage limit from text; no `RUN_FINISHED`.

## 11. R32 incremental cache

Every environment and process used the incremental candidate with the full-history check: **0 check failures, 0 cache errors** across all scenarios; healthy readers had `rebuilt 0` and repair write 0. The cache semantics were not changed for P3.

## 14. Open issues

_(Items 1, 2 and 4 are tracked in the design as the independent open items R36, R37 and R38.)_

1. **A busy thread rejects a headless turn; nothing retries or queues it (R36).** In production terms a scheduled task whose thread has an active browser run would fail (`store.fail`) rather than wait. A policy is needed (wait, retry later, skip, or notify).
2. **A browser run that loses to an active background run is a silent no-op at the HTTP / client surface (R37)** (the real client resolved with no new message). The UX and error code for it are undefined; P3 deliberately did not fix them.
3. The per-thread exclusion lives in one runner **in one process**: multi-process writers (**R17**) were not tested and R17 stays **OPEN**.
4. **The caller still receives only the message of a failed run, not its code (production parity; R38).** The durable `RUN_ERROR.code` is preserved; the headless caller gets a message-only `Error`. A usage-limit UX for headless turns would need a new contract.
5. Production wiring is not done: `Platform.turn`'s `requireReady()`, the removal of `runtimeUrl` / `ownerToken` use, the agent factory, the local `history()`, the scheduler's progress text that names Intelligence, and the creation of conversations for tasks.
6. Only the fake provider was used for headless turns; the voice stand-in is not the real `VoiceService`; `newMessages` is derived with the reducer (equal to the client's in every tested shape: plain, tool, multi-chunk), not proven for every possible event shape.
